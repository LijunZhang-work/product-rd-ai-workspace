# 阶段3：BEH 原生自动验图机器人

## 1. 阶段目标

把 BEH 原生程序当作：

> **Native Oracle / 原生真值验证源**

对于阶段2挑出的可疑 Node / Edge，自动去 BEH：

```text
定位对象
↓
双击
↓
弹出属性窗口
↓
读取 Name / ID / 属性
↓
与 Graph IR expected 值比较
↓
PASS / MISMATCH / UNRESOLVED
```

这一阶段先不要依赖大型 AI Agent。

先证明“固定工具能不能完成单对象原生验货”。

---

# 2. 为什么值得做

即使 BEH 画布：

- 是黑盒；
- UI Automation看不到内部图元；
- DLL/JAR内部不方便接入；

只要：

```text
人眼能看到
鼠标能双击
弹窗能显示属性
```

就仍然可以通过视觉 + 鼠标自动化验证。

---

# 3. 验证对象

## Node

例如：

```text
Graph IR：
Node N177
internal_name = test-3
BEH_display = +
```

机器人：

```text
定位 +
↓
双击
↓
弹窗
↓
读取 Name = test-3
↓
PASS
```

---

## Edge / Relation

例如：

```text
Graph IR：
A.OUT → B.IN
expected_relation = relation_2
```

机器人：

```text
定位 A、B
↓
在 A-B 路径中寻找候选线段
↓
双击线
↓
读取弹窗 relation name
↓
expected vs actual
```

---

# 4. 定位策略

优先级：

```text
1. XML _location / Graph IR Geometry
2. 当前Canvas坐标映射
3. Source/Target Node作为视觉锚点
4. 局部截图视觉定位
5. 放大 / 重试
```

不要让视觉模型从整个大画布盲找。

---

# 5. Relation 点击策略

线很细，可能难点击。

建议：

1. 先找 source node；
2. 再找 target node；
3. 根据 Graph IR 预测线经过区域；
4. 避开交叉点；
5. 优先双击长直线中部；
6. 若弹出的 relation_id 不符：
   - 关闭；
   - 换一个候选位置；
   - 重试有限次数；
7. 仍无法确认：
   ```text
   UNRESOLVED
   ```

---

# 6. 属性读取优先级

不要一上来依赖视觉 OCR。

优先：

```text
1. UIA / Java Access Bridge直接读弹窗控件
2. 聚焦文本框 → Ctrl+A → Ctrl+C → 剪贴板
3. 键盘Tab导航 + 剪贴板
4. 最后才用视觉模型读取文字
```

---

# 7. 固定比较器

比较不交给 AI。

例如：

```text
expected = relation_2
actual   = relation_2
```

固定程序：

```text
PASS
```

否则：

```text
MISMATCH
```

# 9. 不要一开始验所有对象

第一轮只验证：

```text
10个Node
10条简单Relation
```

然后逐步扩展到：

- 多线；
- 交叉；
- continuation；
- 远距离连接。

---

# 10. 批量策略

成熟后：

```text
高可信：随机抽检
中可信：提高抽检比例
低可信：全部验证
Mismatch历史类型：重点验证
```

目标不是让机器人每天点击全部1000根线。

# 12. 阶段3不做

暂时不要：

- 让 AI 自己决定所有点击步骤；
- 自动修改 BEH；
- 自动保存工程；
- 自动创建图元；
- 自己修 Parser；
- 无限重试。

这一阶段只做：

> 原生只读验证。

---

# 13. 阶段3验收

至少满足：

1. Node属性自动核验成功率可接受；
2. 简单 Relation 能自动双击并读到 relation_id；
3. 失败时能给出 UNRESOLVED 而不是乱判；
4. expected/actual由固定程序比较；
5. 有完整截图与日志；
6. 可以从 suspicious_relations.json 批量生成核验任务。

完成后进入阶段4。
