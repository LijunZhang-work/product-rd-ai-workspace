# 阶段5：验证反馈闭环与 AI 写图源准备

## 1. 阶段目标

前四阶段解决：

> 怎么看、怎么审、怎么去 BEH 原生验货。

阶段5解决：

> **怎么让已经发现的问题永久沉淀成系统能力，并为未来 AI 写图源做准备。**

---

# 2. Verified Dataset

建立内部验证数据集：

```text
verified_nodes
verified_edges
mismatch_edges
unresolved_edges
```

每条记录保存：

```text
Graph IR
BEH原生属性
relation_id
source/target/port
scope
parser rule version
verification result
```

---

# 3. Parser / Rule Versioning

任何 Relation 解析规则修改，都有版本：

```text
RULE_RELATION_V7
```

重新跑已有 verified dataset。

如果：

```text
过去100条PASS
现在95条PASS
```

立刻阻止发布。

---

# 4. Regression Suite

建立自动回归：

```text
正确样本
错误样本
边界样本
continuation样本
多relation样本
重复semantic edge样本
```

目的：

> 不让“修一种关系，另一种关系又坏掉”。

---

# 5. Incremental Review

以后新版本 XML / 新 Parser：

不要全部人工重审。

比较：

```text
旧Reviewed Graph
vs
新Reviewed Graph
```

只输出：

```text
新增Node
删除Node
Edge改变
relation_id改变
port改变
direction改变
scope改变
```

用户只审变化部分。

---

# 6. Confidence不再是模型感觉

后期 confidence 应更多来自：

```text
规则是否被原生BEH验证
该relation family历史通过率
是否同scope
是否port完整
是否存在歧义
```

而不是：

```text
AI觉得有80%把握
```

---

# 7. 为 AI 写图源准备 Component Registry

建立：

```text
Verified Component Registry
```

例如：

```text
TON
COMPARE
ADD
Connector
Continuation
...
```

每种记录：

```text
BEH显示符号
内部类型
默认参数
Ports
允许连接方式
原生BEH样本
对应XML结构
隐藏属性
代码附件（如果有）
验证状态
```

---

# 8. 写图源原则

未来 AI 不直接随意写私有 XML。

AI只输出：

```text
CreateNode
SetParameter
Connect
Move
Delete
```

即：

```text
Canonical Graph Operations
```

然后再选择：

```text
BEH Writer
或
BEH Native Driver
```

生成真实工程。

---

# 9. Proposal First

AI新建图元必须先进入：

```text
Proposal Graph
```

在画布上表现为：

```text
半透明节点
虚线Edge
```

经过：

```text
结构Review
+
用户确认
+
必要时原生BEH验证
```

以后才 Commit。

---

# 10. Explain / Compose统一

阶段5以后：

```text
Explain
```

和：

```text
Compose
```

共享同一 Graph IR。

用户可以：

```text
圈一块 → 让AI解释
```

也可以：

```text
圈一块空区域
+
文字
+
草图
→ AI提出新Graph
```

---

# 11. 最终写入闭环

理想最终流程：

```text
用户意图
↓
AI生成 Graph Operations
↓
Proposal Graph
↓
Review
↓
BEH Driver / Writer
↓
BEH原生工程
↓
重新读取
↓
Graph IR
↓
自动比对
↓
PASS / BLOCK
```

这才算真正“AI写图源成功”。

---

# 12. 阶段5验收

至少：

1. 有 verified dataset；
2. Parser规则有版本；
3. 每次修改自动回归；
4. 支持增量 Review；
5. 至少建立 3～5 种 Verified Component；
6. 可以让 AI生成 Proposal Graph；
7. Proposal可以人工 Review；
8. 尚未验证的图元禁止进入正式自动写入。

---

# 13. 一句话总结

> **阶段5不是继续堆 AI 功能，而是把前面的人审、机器审、BEH原生验货结果沉淀成可以回归的工程知识，最终让 AI 写图源建立在“已经验证过的图元和连接机制”上。**
