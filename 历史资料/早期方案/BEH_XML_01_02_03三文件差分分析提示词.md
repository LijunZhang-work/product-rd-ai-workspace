# BEH XML 三文件差分分析任务

## 任务目的

你现在要分析 3 个由 BEH / PLC 图元工具保存出来的 XML 文件。

不要尝试一次性理解整个 BEH 工程，也不要先猜测它遵循 PLCopen、IEC 61131-10 或任何其他标准。

本任务只有一个核心目标：

> **通过对比 01.xml、02.xml、03.xml，找出 BEH XML 中“图元连接关系”和“图形坐标 / 连线路径”分别由什么 XML 数据控制。**

---

# 一、三个文件的已知含义

## 01.xml

画布中有两个图元：

```text
[A]        [B]
```

两个图元存在，但：

> **A 和 B 没有连接线。**

---

## 02.xml

与 01.xml 相比：

- 图元 A 不变
- 图元 B 不变
- 图元位置尽量不变
- 图元参数尽量不变
- 只增加一件事：

> **给 A 和 B 之间增加一根连接线**

画面类似：

```text
[A]────────[B]
```

因此：

> **01.xml → 02.xml 的主要差异，应该包含“新增连接”所需要的 XML 信息。**

---

## 03.xml

与 02.xml 相比：

- A 和 B 仍然保持连接
- 连接关系本身不变
- 图元参数不变
- 只把 B 拖到更远的位置

画面类似：

```text
[A]────────────────────[B]
```

因此：

> **02.xml → 03.xml 的主要差异，应该主要包含坐标、位置、线段路径、折点或布局相关信息。**

---

# 二、最重要的分析原则

## 原则 1：一次只回答一个问题

先回答：

> 01 → 02，到底什么变化代表“从没连接变成连接”？

再回答：

> 02 → 03，到底什么变化只是位置 / 画线方式发生变化？

不要一开始就试图解释整个 XML。

---

## 原则 2：不要根据字段名字直接猜

例如看到：

```text
connection
link
wire
source
target
ref
id
x
y
position
```

不能因为名字像连接字段，就直接认定它一定控制连接。

必须结合三个文件的实际变化来判断。

---

## 原则 3：以实验差异为最高事实

如果某个字段：

- 01 没有
- 02 出现
- 03 仍然存在且基本不变

那么它很可能与：

> **连接关系**

有关。

如果某个字段：

- 01 和 02 基本相同
- 02 → 03 明显变化

那么它很可能与：

> **坐标 / 布局 / 连线路径**

有关。

---

## 原则 4：不知道就明确写 UNKNOWN

禁止为了“完成任务”而猜测。

如果证据不足，请直接写：

```text
UNKNOWN
```

并说明：

- 为什么无法确定
- 当前有哪些可能
- 还需要什么实验才能确认

# 三、第一步：先确认三个文件是否真的可比

首先检查：

- 三个文件的 XML 根节点是否相同
- 工程 / 页面 / 图元数量是否符合预期
- 01 和 02 是否真的只是多了一条连接
- 02 和 03 是否真的主要只是图元 B 被移动
- 是否存在自动生成的时间戳
- 是否存在随机 GUID
- 是否存在保存次数
- 是否存在自动重新编号
- 是否存在 checksum / hash
- 是否存在 XML 元素排序变化

如果存在这些无关变化：

> **不要把它们误认为连接关系。**

请单独列为：

```text
Noise / 保存噪音
```

# 六、必须检查的四种连接可能

不要只检查一种。

## 可能 1：图元直接引用图元

例如：

```text
A → B
```

XML 可能类似：

```xml
<connection source="A" target="B"/>
```

或：

```xml
<block id="B">
    <input ref="A"/>
</block>
```

如果发现这种结构，请给出证据。

---

## 可能 2：通过端口连接

可能是：

```text
A
↓
A.outPort
↓
连接
↓
B.inPort
↓
B
```

也就是说 XML 并不是直接记录：

```text
A → B
```

而是：

```text
A.out1 → B.in1
```

请检查：

- port
- pin
- terminal
- input
- output
- parameter

一类对象。

---

## 可能 3：通过第三方 Net / Wire 对象连接

可能是：

```text
A → Net123 ← B
```

或者：

```text
A.port → Wire57
B.port → Wire57
```

此时 A 和 B 并不会直接引用彼此。

重点检查：

> **A 和 B 是否共同引用同一个第三方 ID。**

---

## 可能 4：通过坐标重合建立连接

也可能没有明显的：

```text
source
target
refId
netId
```

而是：

```text
A 的输出端坐标
=
Wire 的起点坐标
```

以及：

```text
Wire 的终点坐标
=
B 的输入端坐标
```

软件加载时通过几何位置推断连接。

如果找不到 ID 引用关系，请认真检查这种可能。

# 十二、本轮任务什么时候算完成

不是“看懂整个 XML”才算完成。

> **第一：BEH XML 里，什么信息主要决定“两个图元是否连接”。**

> **第二：什么信息主要决定“图元和连接线在画布上怎么摆、怎么画”。**
