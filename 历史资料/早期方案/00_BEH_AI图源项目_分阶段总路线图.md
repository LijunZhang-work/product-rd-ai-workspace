# BEH AI 图源项目：分阶段总路线图

## 1. 当前背景

当前项目已经具备一些重要基础：

- 能解析 BEH 私有 XML 中带 `_location` 的关键元素；
- 能按照原始坐标将这些元素放到可视界面上；
- 已经开始恢复 relation / 连线 / 箭头；
- 已经定义“簇”作为局部分析单位；
- 已经设计 Graph IR、Review、Selection Pack、Intent Pack 等中间结构；
- 长期目标是让 AI 不仅能“读懂图源并给小白解释”，还能够与人一起“写图源”。

但目前真正的难点集中在：

1. 线 / relation 的识别和身份容易不准；
2. 图画得“看起来对”不代表底层 relation_id、端口、作用域一定对；
3. 人工逐条双击 BEH 中的几百、几千条 relation 做核对不可行；
4. BEH 原生界面可能是黑盒，外部工具未必能直接读到画布内部对象；
5. 公司侧模型能力有限，因此不能把所有精确工作都压给单一 AI。

因此后续开发不应一次性做“大而全”的 AI 图形 IDE，而应该分阶段收敛。

---

# 2. 总体阶段

建议拆成 5 个阶段。

```text
阶段1
统一图源工作台基础
Graph IR + 原始坐标 + Reviewed Edge + 圈选解释
        ↓
阶段2
高效人工 Review 与 Relation 身份审计
人眼可快速判断图元和拓扑，机器严格核 relation_id
        ↓
阶段3
BEH 原生自动验图机器人
自动双击 BEH 元素/线，读取弹窗属性并比对
        ↓
阶段4
DeepSeek Harness + 小视觉模型 Agent 化
AI负责规划，视觉负责定位，固定工具负责操作和比较
        ↓
阶段5
验证反馈闭环与 AI 写图源准备
错误样本沉淀、回归测试、规则收敛，为未来生成图源打底
```

---

# 3. 阶段之间的依赖

## 阶段1必须先完成

因为后面所有 Review、验证、AI解释都必须围绕同一个：

```text
Graph IR
```

不能一边让人看 SVG，一边让 AI重新读 XML 得出另一套关系。

---

## 阶段2不能跳过

阶段2解决：

> “图看起来差不多，但到底哪些地方不可信？”

它建立：

- 图元显示模式；
- relation_id 机器审计；
- 节点邻域 Review；
- 可疑关系队列；
- Edge Provenance。

没有这一层，阶段3的自动验货机器人也不知道“应该去 BEH 验什么”。

---

## 阶段3先于阶段4

阶段3先把：

```text
截图 / 定位
双击
读取弹窗
复制属性
expected vs actual
```

做成尽量固定的工具。

阶段4才让 AI接入。

这样可以避免：

> 自动验图做不好，却误以为只是模型不够强。

---

## 阶段5不是简单“加更多功能”

阶段5主要解决：

> 如何让已经发现的错误永久消失，而不是每次重新人工检查。

它会建立：

- 回归样本；
- verified relation dataset；
- mismatch dataset；
- parser / rule 版本；
- 增量 Review；
- 未来 AI 写图源需要的 verified component template。

---

# 4. 各阶段最终成果

| 阶段 | 主要成果 | AI 是否必须参与运行 |
|---|---|---|
| 1 | 统一 Graph IR + SVG/Sprotty 工作台 + 圈选解释 | Explain 时需要 |
| 2 | 人工 Review 工作台 + relation 身份审计 | 可选 |
| 3 | BEH 原生验图工具 | 不必须 |
| 4 | Harness 多模型自动验证 Agent | 是 |
| 5 | 回归闭环 + 写图源准备 | 部分需要 |

---

# 5. 项目长期终态

最终希望形成：

```text
                    人
        拖图 / 圈选 / 草图 / 自然语言
                    │
                    ▼
             Canonical Graph IR
                    ▲
                    │
                   AI
          理解 / 解释 / 生成 / 修改
                    │
                    ▼
                Review Layer
                    │
              ┌─────┴─────┐
              ▼           ▼
        原始可视工作台    BEH Native Validator
              │           │
              └─────┬─────┘
                    ▼
                Verified Graph
                    │
              ┌─────┴─────┐
              ▼           ▼
          BEH Writer     BEH Driver
              │           │
              └─────┬─────┘
                    ▼
                 BEH 工程
```

核心思想：

> **AI负责理解和意图；固定程序负责事实、验证和确定性转换。**

---

# 6. 当前推荐执行顺序

现在不要同时开发 5 个阶段。

建议：

1. 固化阶段1；
2. 马上进入阶段2；
3. 阶段2能够列出“哪些 Node / Edge 需要原生核验”后，再开发阶段3；
4. 阶段3能够稳定完成单对象核验后，再接 Harness 进入阶段4；
5. 阶段4达到批量可用后，进入阶段5。

---

# 7. 一句话总纲

> **先把图变成可信、可审计的结构化事实，再让人快速 Review，再让机器人去 BEH 原生界面验货，最后才让 AI Agent 自动编排整个验证流程。**
