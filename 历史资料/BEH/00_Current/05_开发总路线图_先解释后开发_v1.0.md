# 开发总路线图：先解释，后开发；先 MVP，后精修

## 阶段0：原生 Headless 场景底座固化

目标：把已验证“完全可行”的 Headless Full Scene 变成稳定契约和可回归服务。

交付：

- scene.svg；
- scene.json；
- hit-map.json；
- properties；
- diagnostics；
- Golden样本；
- Hash与缓存。

退出条件：小样本结构与原生 BEH 一致，接口稳定。

## 阶段1：Web 查看、圈选与任务导出 MVP

目标：用户可以配置工作区、选择 POU、查看原生图、点击和圈选、导出任务。

MVP只做：

- 左侧POU树；
- 中央原生SVG；
- 右侧可折叠“选择详情”；
- 底部可折叠“代码占位/诊断”；
- 矩形、椭圆、Lasso；
- 结构化箭头/文字标注；
-导出JSON和AnalysisTaskBundle；
- Playwright验证。

不做：AI解释、复杂手绘识别、主题精修。

## 阶段2：AI 解释 MVP（外置 Skill）

目标：Web不接API，人通过外部Harness运行分析Skill，结果写回任务目录。

先支持：

- 输入/处理/输出；
- 每个元素依次做什么；
- 选区边界联系；
- 专业版；
- 小白版；
- 基础代码引用；
- 分析步骤联动画布。

不做：正式图元修改和代码写入。

## 阶段3：代码仓关联与解释准确性增强

目标：基于完整代码仓和真实编译配置提升解释。

增加：

- compile_commands；
- clangd/Clang索引；
- call graph；
- def-use；
- scene-code binding；
- C/C++路径证据；
-降级状态；
-回归数据集。

## 阶段4：AI 开发图元与 C/C++ 候选 MVP

目标：AI根据区域、文字和结构化草图提出：

- Graph Operations Proposal；
- CodePatch Proposal；
-影响范围；
-验证计划。

仅Proposal，不应用正式工程。

## 阶段5：原生应用、Round-trip与安全提交

目标：通过原生 BEH 能力应用 Graph Operations，保存后重新加载，验证Scene和模型等价；代码补丁经过构建/测试后才允许提交。

## 阶段6：Workbench 与 DeepSeek Harness 一体化

目标：替换人工文件传递，但不改变Task/Result契约。

```text
Analysis Gateway
├─ FileBundleAdapter
└─ HarnessAdapter
```

## 阶段7：精雕细琢（后置）

- 高级视觉主题；
- 动画；
- 复杂草图视觉理解；
- Semantic View；
-高级图元库；
-多人协作；
-智能推荐；
-更细性能优化。

## 阶段推进规则

每阶段都必须：

1. 完成最小闭环；
2. 通过自动测试；
3. 通过实际运行验证；
4. 形成Golden样本；
5. 记录限制；
6. 满足退出条件。

禁止“阶段功能没有跑通，先去美化界面”。
