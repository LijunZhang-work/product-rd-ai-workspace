# 产品研发与测试 AI 统一工作区：整理方案（重审版）

日期：2026-09-17｜状态：建议方案，未执行迁移｜范围：现有 BEH 与网页人工路径测试两个工作区。

## 1. 决策建议

建议统一到 **/产品研发与测试_AI统一工作区**。采用“功能模块为主、完整组件保留、公共能力单一归属、一次任务统一记录”的方式。

不采用只在新目录下并排放两个旧工作区的长期结构；那样端到端、Trace、解释与开发的归档问题仍在。也不把每份文件按出现的关键词拆开：一个可运行组件的安装说明、实现边界、版本验证报告和发行包需要能一起找到。

本方案是资料组织建议，不要求合并代码仓、Runner、数据格式、Java/Python 环境或运行服务。当前主线仍是产品端到端测试与解释；问题定位和 AI 图元开发有独立入口，依赖现有能力逐步推进。

## 2. 本次重新核对了什么

对两个目录完整列举：BEH 工作区 94 个文件、27 个子目录；网页人工路径工作区 9 个文件、无子目录，共 103 个文件。列举无剩余分页。计数不含本方案。

在前轮已读各模块入口、测试指南和验证报告的基础上，本轮重点复核：原生 MCP 指南、NativeScene 与 HitMap 契约、AI 图元开发候选、工作台 Playwright 测试、人工路径使用与实现边界、AnalysisTask/Result、Selection/Intent、Proposal/CodePatch、原生场景底座、源码关联、旧代码仓结构及维护规则。

没有逐份重新通读全部历史文件，没有展开 ZIP、复验封存摘要或执行软件。附录逐文件映射是一份完整的**建议迁移清单**；历史项沿用既有归档结构，不是逐项内容去重结论。标题相同、大小相同不足以证明文件可删除。

## 4. 为什么不是简单的“把 AI 测试并入 BEH”

两边不是同尺度的系统：BEH 工作区已是跨功能的设计集合；人工路径项目是有独立版本和执行规则的浏览器组件。

人工路径 v0.1.0 的实现说明明确存在固定执行器、独立预期、证据快照与版本复用；未覆盖原生 Java、Canvas/BEH 图元等。把它放入更大工作区，不代表已经接入用户产品，也不意味着其 UI-only 测试可改走业务接口。

BEH 则既是对象模型和原生能力来源，也参与解释、行为测试与图元开发，不能把全部 BEH 文件塞进“桌面控制工具”目录。

因此保留两种入口：用户按“我要测试／解释／定位／开发”进入；实施者按“BEH／网页人工路径组件／485 工具”等找到具体能力。每份文件只有一个主位置，另一入口用索引指向。

### 5.1 AI 测试内部的安排

- **产品端到端**：协调产品网页、BEH、北向、南向 Python、专用 RS485、日志解析的一条业务场景。
- **图元行为测试**：FB/CB 的真实运行、已有基线、适配与业务断言。
- **网页人工路径**：保留原项目的完整组件身份，第一轮 9 个文件整体进入这里。
- **测试与解释融合**：放两者协作的执行流程；解释原则和解释输出格式仍由 20 维护。

网页人工路径组件当前只有 9 个文件，第一轮无需拆细。以后按版本增长时再区分当前说明、历史设计、发布包，并更新组件入口。

### 5.2 工具接入与共享能力内部的安排

建议按需设置 BEH 原生能力、工具选型与接入调查、浏览器与桌面控制、外部工具接入、代码关联与宿主接入、信号追踪与运行观测、运行记录与公共字段。

外部工具接入中明确区分北向工具、南向 Python 模拟脚本、专用 RS485 模拟工具。控制某个工具的 Python 包装不改变它原来的来源身份。

BEH 原生能力可包含连接/调试/观测、场景与对象。原生编辑的完整开发闭环仍由 40 负责，60 引用其中的接口调查；有独立可复用 Bridge 后，再给该 Bridge 明确唯一的使用说明位置。

## 7. 三层信息：方法、组件、实例

1. **方法与规则**放在功能/公共模块，例如如何判断断点是否命中。
2. **可运行组件的说明与发行物**保留组件版本身份，例如人工路径 v0.1.0 的安装包和自身验证报告。
3. **某次使用组件完成产品任务的记录**进入 70，例如某个固件版本上的一次端到端测试。

组件自身资格验证与产品业务测试是两种证据。历史 HPT 实测证据包继续跟随对应组件发布；70 可以引用其中某次 run，不为归档方便解包改写或重复上传。

70 的建议逻辑层次是“产品/工程身份 → 任务身份 → 多次运行和派生结果”。目录名格式按现有 Runner 能力适配，不强制它更改原生输出。先用索引引用既有证据路径即可。

一项任务可以有多个运行、重试、解释和修改候选：已有 run_id 不重命名，跨工具以来源命名空间和版本关联。解释可指向某次运行的具体证据；修复后的验证是新运行，不能覆盖旧失败。某次 AI 开发也可能没有先发生故障，应能独立创建任务。

## 8. 保留独立语义，不为了统一目录统一所有 Schema

HPT 的行为契约、固定 UI 路线、独立预期和证据封存继续适用。端到端层可以组合它与 BEH/协议工具，但不能为通过而把 HPT 被测网页步骤改成 API。

BEH 图元实例、设备信号、源码符号、浏览器控件不是同一种 ID。可建立带来源、版本和依据的映射，不强迫改成一个全局字符串，也不依据同名自动绑定。

当前 HPT 可运行 schema 为 1.1；较早设计中的示意不是可以覆盖实现的格式。BEH 专用契约多数属于设计资料，本次未验证本地实现。公共层第一步仅定义可用的索引/引用，不要求改写所有既有结果。

这种安排可以为未来网页减少返工：网页读取公共任务索引，并按类型打开原生 Trace、观测、解释和开发候选；展示层不重新解析一套图元真相。

## 10. 阅读顺序与状态，解决比路径更深的混淆

每个模块入口维持一个短表：主题、当前主文件、适用范围、实现/验证状态、相关组件、历史替代关系。默认阅读顺序为总入口 → 任务相关模块入口 → 指定主文件 → 必要参考，不要求 AI 通读整个工作区。

状态至少区分：方案/待验证、用户反馈已跑通、有适用环境运行证据、已替代。它们不能单纯按文件创建日期排大小：新设计不否定既有实测，也不能把旧局部实测扩展成整条链成功。

特别要写清几项已有口径差异：

- 旧阶段 0～6 与 MCP 的“第一阶段”不是同一编号体系。
- 旧“先解释后开发”的线性阶段不覆盖现在按能力并行推进的主线。
- 早期无源码或特定 JCanvas 限制需注明适用版本/证据，不能扩大成当前所有接入方式的禁令。
- 人工路径“已验证”限定于其报告环境与夹具，不能升级为 Windows 真产品已验证。
- 旧 Monorepo 文档属于软件架构参考；资料目录统一不触发代码仓合并。
- 图元开发与问题定位是两个功能入口，不能把新图元创建流程降格成故障报告。

当前会话明确的新要求优先；保留原有真实证据和适用边界，避免整理目录时偷偷改变测试或编辑许可。

## 11. 三种整理选择的比较

| 方案 | 优点 | 问题 | 判断 |
|---|---|---|---|
| 保留两个根，只加导航 | 几乎不移动文件 | 后续跨模块文档仍要选择根目录，继续积累歧义 | 可作迁移过渡，不适合作长期终态 |
| 新根下完整保留两个旧根 | 保持老项目打包完整 | BEH 根内仍混合跨系统流程；统一只发生在名称层 | 不推荐作为终态 |
| 一个根、功能模块＋完整组件＋公共能力＋任务记录 | 日常归档明确，组件仍可独立使用，支持后续图元开发 | 需要一次受控迁移和入口调整 | **推荐** |

选择功能划分不是认为测试、解释、开发互不相关；共同的任务、版本、对象和证据引用负责把它们连接起来。文件夹只解决主要维护位置。

## 12. 真正执行时的迁移顺序

本轮只产出方案。以后执行整理时，按以下顺序推进，不把旧文件复制为另一套长期维护副本。

1. **核对基线。** 重新列举两个根，与本附录对照；期间新增文件补入清单、修改过的文件保留最新身份和版本。当前 103 不是永久固定数量。
2. **建立目标入口与必要目录。** 以一个根为最终入口；先准备主文件清单和旧新路径对照。是否通过新建或重命名完成，由实际目录条件决定，目标结构一致。
3. **按身份移动现有文件。** 第一轮尽量保留文件名和内容；HPT 9 个文件整体进入组件位置；BEH 按附录映射；历史子树保持内部结构。迁移日志逐项记录成功/失败。
4. **更新活文档的入口和链接。** 优先统一入口、模块入口和当前实施指南。同一文件编辑保留身份，不能创建“最终2”。不可把 Library 路径修改误写成公司电脑路径已同步。
5. **保留历史与包内快照。** 不改封存 ZIP 内容、旧 run 的摘要与结论；旧迁移清单移到历史记录并由新索引引用，形成原路径→现路径的链。重复候选只标记，不据文件名删除。
6. **检查兼容与数量。** 每个原文件有一个有效目标；新旧导航无断链；同名不覆盖；组件入口能找到对应包和说明；其他工作区没有被移动。
7. **切换日常归档。** 更新当前导航与后续默认路径。旧根短期可以只留下“已迁移”的说明和目标路径，不再增加业务文件；无需同时保留两套完整内容。新的包应重新注明发布日期和包含范围。
8. **内容整理后置。** 仅对已经确认重复或冲突的活文档做合并/修订，注明替代章节；历史资料不是因为旧就失效，专题规则仍可适用。

迁移中断时根据逐项日志继续；需要回退时按映射把文件移回，保留已编辑版本记录，不用复制整套文件作为回退策略。验收针对归档和引用，不重复执行产品或 GUI 测试。

## 13. 三个最小新入口

执行时新增的内容优先保持少量：

- **统一入口与当前主文件表**：回答现在做什么、各模块读哪份、功能做到哪里。
- **问题定位模块入口**：明确目标、引用测试/源码证据的方法、与新图元开发的区别；不把方案写成已实现。
- **任务记录与公共引用说明**：定义任务、run、版本、对象映射、原始证据与派生解释的关系；先适配现有格式。

其他现有模块入口主要调整范围、链接和当前状态。公共契约索引可以是入口中的一张表，不必再搭注册服务或新数据库。
