# BEH 已知问题与观测适用边界

版本：v1.0｜2026-09-20｜本文件集中维护 BEH 观测问题及能力适用范围；证据评价的公共规则仍以[证据矩阵](../../总览与规则/参考规范/02A_按事实域划分的证据可信度矩阵_v1.0.md)为准。

## 1. 记录来源与当前状态

以下来自用户在本窗口的实际使用反馈。作者本轮未连接产品、未取得对应代码和原始记录，尚未独立复现；具体 BEH/固件/模型版本、触发条件和根因待本地补证。不能将其他历史版本事故的版本号自动套在这两个问题上，也不默认所有版本都有相同缺陷。

| 编号 | 用户观察 | 当前可支持的判断 | 尚不能支持的判断 |
| --- | --- | --- | --- |
| BEH-OBS-001 | 在线 Debug/断点查看时，同一变量后续更新后，前面图元位置的显示也变化；可出现看似 `-14 > 0` 为真的画面 | 该显示不能未经核对当作早先运算使用值；需查当前监视值与执行快照是否混用 | 已证明板上比较运算错误；已证明具体缓存/刷新实现是根因 |
| BEH-OBS-002 | 开启图形工具 Debug 时，产品 C++ 打印值偶发 `5 → 0 → 5`；关闭后现象消失 | Debug 状态与现象存在用户观察到的关联，应单独控制和记录 | 已证明工具主动改写变量；已排除业务竞态、暂停/负载或打印时机问题 |

新证据追加版本、实际复现步骤、日志/事件/画面路径与摘要、采集条件、结论范围。保留用户观察与后续验证的区分；不能为了补齐表格把猜测写成已证实根因。

## 2. 按能力和结论限定可信度

| 能力或证据 | 能证明什么 | 使用条件与限制 |
| --- | --- | --- |
| 原始 JAR 的解析、模型和渲染 | 该版本、该输入下工具实际怎样表现 | 可以含自身缺陷；行为兼容性不等于业务正确 |
| XML 与生成/绑定资料 | 输入定义、实例/端口、生成关联 | 核对版本和实际装载；同名或坐标不能替代绑定证据 |
| GUI 在线显示 | 当时界面显示了什么 | 需确认来源、缓存、刷新时刻、实例和执行阶段，才能进一步用于产品执行结论 |
| Headless/POU Runner 结果 | 该引擎在明确条件下执行所得 | 查运行入口和取值通道；无 GUI 不自动等于绕过有问题的实现 |
| 板端采集/C++ 打印/数据库记录 | 该取值点在明确条件下观测到什么 | 同样核实实际使用值、原子性/生命周期、身份、丢失及扰动；“直接”不等于无误 |
| 业务规范/独立断言 | 在规定条件下应该怎样 | 记录适用版本和前提，不能由当前实现输出反向定义 |

同一 JAR 的 GUI 和 Headless 可能共享解析/算法实现，两者一致不能算两个独立业务正确性证明。独立的转换/采集链也要验证，不能仅凭换成文件就升格。

## 3. 本地 AI 如何处理两类问题

对 BEH-OBS-001，定位变量值来源、显示绑定、缓存/刷新、暂停位置和图元结果来源。用可控状态变化比较实际操作数、结果、调用/周期和阶段；验证前面位置表示“当前监视值”还是承诺的“该次执行值”。若功能只提供当前监视值，就按该语义使用；若明确声称是历史执行值而发生替换，记录相应显示/时刻绑定缺陷。不能用后续值解释先前分支。

对 BEH-OBS-002，在同一版本、同一业务条件下进行 Debug 关闭/开启的可比实验，记录断点/暂停、负载、任务进度、采集代码和实际事件身份。先查观测通道有无写入/强制值/同步状态的行为，再查时序与并发影响及打印位置。实验未再出现只能说明该次未复现，不能消除偶发问题。不要为观察偷偷增加业务锁、屏障、重试或修改调度，以免掩盖原现象。

不要求修复全部 BEH 在线问题才能继续离线 POU 测试。确认某项离线入口不依赖受影响通道且具备其所声明的执行证据后，可继续使用该范围；无法确认的结论标为受影响或待核对。新场景默认用独立核实的产品采集，BEH 在线 Debug 作为专门对照条件，不能静默开启。

## 4. 运行记录的最低解释条件

每个关键结果能回溯到源码/固件/模型/引擎版本、设备和 POU 实例、采集会话、消息/执行身份、周期/阶段、取值方式、质量及 Debug 开关状态。时间戳包括单位与来源；采样、接收、执行和入库不是同一时刻。缺失时限定结论，不拼接成虚假的同时快照。

逐次执行记录应复制原代码当次实际使用的值；多个字段或阶段不具备一致快照时明确标识。缓冲溢出、过滤、未插桩、未导出和实际未执行分别考虑，不能以日志缺项证明业务没发生。只记录最终值或稀疏趋势时不得标“逐拍已验证”。

## 5. 对其他模块的统一约定

- AI 测试：板端实际、离线实际和独立预期分开；POU 支持范围以已有入口和证据核实，不退回只支持 FB 的旧起点。
- AI 解释：明确讲的是当前显示、某次执行记录、静态推导还是业务规范；证据不足不补全内部时刻。
- 上板采集：选择合适取值点并评估扰动；文件、打印和数据库都不是无条件正确的通道。
- Golden/网页工作台：标明样本用途是原工具表现兼容、结构绑定还是业务正确；已知原工具缺陷可以保存为缺陷样本，不能悄悄当成业务正确标准。
- 问题定位：分开现象、首次异常、机制原因和根因；显示矛盾本身不证明产品算法出错。
