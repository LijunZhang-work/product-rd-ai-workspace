# 阶段3：代码仓关联与解释准确性增强

## 1. 目标

让分析真正结合完整代码仓，而不是只看同名字符串。

重点支持 C/C++：

- 定义；
-引用；
-类型；
-调用；
-参数；
-返回值；
-宏和include环境；
-有限Def-Use；
-图元到代码绑定。

## 2. 工作区必填/选填

### 必填

- 代码仓根目录；
-主入口XML；
-BEH运行时；
-当前构建Profile。

### 强烈建议

- `compile_commands.json`；
-目标平台；
-宏配置；
-生成代码目录。

缺少编译数据库时，UI必须显示“降级分析”。

## 3. Code Intelligence分层

### L1：编译语义

clangd/Clang基于真实编译命令。

### L2：结构语法

Tree-sitter。

### L3：文本搜索

ripgrep。

### L4：AI推理

必须标为HYPOTHESIS。

## 4. Scene-Code Binding

绑定证据：

```text
DIRECT_NATIVE_BINDING
GENERATED_MAP
EXACT_SYMBOL
UNIQUE_REFERENCE_PATH
DATA_FLOW_INFERENCE
AI_HYPOTHESIS
```

每个绑定保留来源。

## 5. 数据流步骤

目标不是声称“完全理解所有运行时行为”，而是分级：

- 图元内部原生语义；
-图元间Relation；
-绑定变量；
-函数内Def-Use；
-跨函数参数/返回；
-跨模块；
-运行时不可证明。

## 6. 性能

- 后台增量索引；
-按需查询；
-结果缓存；
-索引进度；
-可取消；
-限制单次Evidence大小；
-避免将全仓文本放入Task Bundle。

## 7. 测试

- 小型C仓；
-小型C++类调用；
-宏分支；
-同名符号；
-多编译Profile；
-缺失compile_commands；
-生成代码映射；
-无绑定场景。

## 8. 解释准确性验收

每个代码断言都必须可跳转到：

```text
file + range + symbol + evidence_type
```

无法跳转的结论不得标为HIGH。
