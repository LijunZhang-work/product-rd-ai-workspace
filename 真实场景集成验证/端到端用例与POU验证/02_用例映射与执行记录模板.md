# 用例、映射与执行记录模板

配合[场景方案](01_场景实施方案.md)使用。以下是字段模板，没有真实产品值；复制所需结构到一个实际[任务记录](../../任务记录/任务记录模板.md)，不把空表算作完成。优先适配现有 Runner/采集格式，不为统一格式重建系统。

## 1. 任务与已有成果

| 字段 | 填写内容 |
| --- | --- |
| task_id / 场景方案 | 实际标识、本文及方案修订 |
| 本次范围 | 不上板／上板／两者；不适用和受阻分别说明 |
| 专业确认人及业务依据 | 原始端到端用例、需求/设计、待确认问题 |
| 双仓事实成果 | 实际报告路径、源码/配置身份、原始工具证据、复用与失效范围 |
| XML/绑定成果 | 模型版本/摘要、实例/端口、映射来源及证据 |
| 测试入口 | 现有 Runner/Runtime 版本、真实调用方式、已知限制、是否经过在线 Debug |
| 环境与工具引用 | Windows与WSL开发环境 的已有成果、唯一工具报告修订/摘要/实例；不复制台账 |
| 编译数据库 | 每仓/配置的实际路径、来源、版本/参数/关键覆盖、复用或补齐结论 |
| 进度 | S0～S7 各步状态、证据、缺口、最后动作和续接点 |

## 2. 独立业务用例

| 字段 | 填写内容 |
| --- | --- |
| case_id / 业务意图 | 来源用例 ID、要检验的规则 |
| 初始条件 | 参数、模式、设备连接、保持状态、复位/初始化或预热策略 |
| 外部动作序列 | 入口、顺序、值及单位、时间/事件条件 |
| 应有外部结果 | 业务断言、时间范围/容差、独立依据、确认状态 |
| POU 边界 | 实例/模型、包含的上游、跳过段、全局/外部依赖 |
| 预期粒度 | 精确值／范围／时序／不变量／待确认；不能唯一推导时说明 |

## 3. 唯一信号与端口映射表

每条实际关系一行，允许拆分、合并、一对多、多对一和替代关系；不强行一信号对应一个端口。

| 字段组 | 必填内容 |
| --- | --- |
| 身份 | mapping_id、设备/点位、产品对象/字段、EMAP 组件/消息、POU 实例/端口 |
| 构建与证据 | 源码/模型/配置版本、文件/符号、静态查询/生成映射/运行证据引用 |
| 转换 | 原始类型/位宽/编码、单位/缩放、质量/有效/使能、适用转换规则 |
| 时序与状态 | 来源时间语义、接收/应用/消费阶段、周期/事件、状态或反馈依赖 |
| 关联 | 请求/消息/数据版本、父子/合并关系、跨域映射依据；歧义明确标注 |
| 结论 | 已证实／条件推导／候选／未知；缺口及补证动作 |

## 4. POU 测试与回放数据

原生格式可不同，但必须表达：`case_id`、模型/Runner 身份、参数与初始状态、连续 steps/events、每步逻辑时间/输入/质量/使能、执行推进方式、断言和依据。

每个值标来源：规范/配置确定的输入、静态条件推导、真实上游主机执行、板端实测、测试设定。未知使用明确缺失值和原因，不用数值 0 或空字符串冒充。板端数据转换时保留原文件及事件定位；必要的浮点位模式/类型信息不得在格式化中丢失。

测试断言记录 expected、依据、适用条件和容差；实际输出另存 actual。板端输出作为 observed_board，对照用 observed_offline，禁止从 actual 自动生成 expected 后宣布业务通过。

## 5. 采集点与会话配置

| 字段组 | 填写内容 |
| --- | --- |
| 实际点位 | point_id、程序/执行域、源文件/函数、设备接收/转换/交接/消费/输出/机制类型 |
| 触发方式 | 收到数据／对象更新／调用或周期／机制事件／定时背景；理由和覆盖边界 |
| 内容 | 原代码实际使用的值、类型/单位、质量、消息/版本、决策及阶段 |
| 安全取值 | 生命周期、已有局部值复用、并发一致性；额外读取或副作用风险 |
| 范围 | 选定设备/信号/POU、预计峰值事件率、记录长度、容量和窗口 |
| 控制 | 现有开关入口、配置版本、各域开启/关闭应答、生效序号、异常触发 |
| 保存 | 本域缓冲、溢出策略、丢失统计、实际导出通道、数据库/文件落点 |
| 取证边界 | 文件系统是否可用、失效 IPC 的备用导出、是否要求且能否跨复位保留 |
| 验证 | 构建/装载身份、记录开关对照、耗时/负载/丢失、已知样本解码结果 |

每个会话保存 capture_id、各域 boot_id/build_id、原始时钟单位/同步误差、开关/Debug 状态、起止序号、丢弃/覆盖/未导出统计、模型/映射/事件格式身份。capture_id 不代替消息关联；入库时间不代替发生时间。缺字段保留为空并写原因，不伪造源设备时钟。

## 6. 结果、Review 与续接

| 比较项 | 板端实际 | 离线实际 | 独立预期 | 条件/证据/结论 |
| --- | --- | --- | --- | --- |
| 按实际断言逐行填写 | 未采到则明确 | 未运行则明确 | 待确认则明确 | 不将不同阶段或实例混合 |

Review 至少检查：实际边界是否完整、状态/时间能否还原、输入转换是否可复核、预期是否独立、采集关联及丢失是否影响结论、Debug 是否介入、首次异常是否被误当根因、原始记录和复跑命令能否找到。

每个问题记录发现、影响、修改、复验及剩余限制。任务总结引用这些结果；本模板和场景目录不再保存第二份数据。阶段结果允许部分完成，必须指出下一项必要动作。
