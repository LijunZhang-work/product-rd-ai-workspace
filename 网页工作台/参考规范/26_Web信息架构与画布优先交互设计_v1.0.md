# Web 信息架构与画布优先交互设计

## 1. 核心原则

画布是主角。任何长期占据面积的侧栏都必须可折叠。

## 2. 布局

```text
┌───────────────────────────────────────────────────────────┐
│ Workspace / XML / POU / Scene / Index / Task             │
├──────────┬───────────────────────────────┬────────────────┤
│ 左侧树    │                               │ 右侧Dock       │
│ 可收窄    │       Native Scene Canvas     │ 可折叠/拖动     │
│          │                               │               │
├──────────┴───────────────────────────────┴────────────────┤
│ 底部Dock：代码/诊断/日志，可折叠/拖动                      │
└───────────────────────────────────────────────────────────┘
```

## 3. Dock行为

- 右侧和底部独立折叠；
-折叠后保留窄标签；
-支持拖拽；
-记忆用户尺寸；
-一键纯画布；
-展开不重置zoom/pan/selection；
-小屏优先抽屉。

## 4. 顶部准确用词

- “导出分析任务”或“准备分析任务”；
-“任务状态”；
-“场景状态”；
-“代码索引状态”。

初期不得出现“发送给AI”“AI在线”。

## 5. 工具模式

```text
浏览
点选
矩形
椭圆
Lasso
箭头
文字
自由笔
```

Compose尚未开启时，工具栏不展示正式图元创建按钮。

## 6. 右侧Dock

页签：

```text
选择详情
分析结果
证据
任务
```

- 选择详情：当前实时选择。
- 分析结果：只读Result Bundle。
- 证据：Native IDs和代码Evidence。
- 任务：准备/完成/失败。

## 7. 底部Dock

页签：

```text
代码关联
诊断
运行日志
```

代码区只读；Compose后再增加Diff。

## 8. 结果联动

点击分析步骤：

- zoom/focus；
-高亮Node/Relation；
-显示步骤编号；
-代码跳转；
-证据同步。

点击图元/Relation：

- 定位相关分析步骤；
-显示原生属性；
-显示代码绑定。

## 9. 视觉模式

```text
原生显示
内部身份
混合
```

原生显示来自Headless scene。内部和混合通过Overlay显示，不改原生SVG语义。

## 10. 选择结果卡

显示：

- Node数；
-Port数；
-Relation数；
-边界Incoming/Outgoing；
-Unknown；
-导出JSON；
-准备分析任务。

## 11. 可访问性

- 键盘可操作；
-可见焦点；
-足够Hit Area；
-颜色不作为唯一状态；
-提供文字状态；
-减少动画选项；
-面板折叠有ARIA状态。

## 12. MVP视觉范围

先保证：

-层级清楚；
-文字可读；
-画布最大；
-选择状态明确；
-错误可见。

高级材质、动效和视觉品牌放入后置文档。
