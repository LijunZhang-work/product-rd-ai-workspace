# 网页工作台：模块入口

> 2026-09-20 观测规则：解释或定位 BEH 值时，先引用[BEH 已知问题与观测适用边界](../工具接入与共享能力/BEH原生能力/BEH已知问题与观测适用边界.md)。界面当前值不能直接证明早先执行值，Debug 对运行的影响要核实；引擎实际输出和业务应有结果分开。

日期：2026-09-14

## 职责
网页工作台是人看图、圈选、提出问题、查看解释和测试证据、审核开发候选的界面。“外置 Harness Skill”只是早期任务执行方式；工作台统一叫网页工作台。
复用原生场景事实：scene.svg、scene.json、hit-map；网页承担命中、圈选、标注、高亮和结果展示。保持画布优先，右侧与底部可折叠。已有底座可行不等于所有交互已完成验收。

## 与四模块配合
- 解释：显示“基础解释 / 测试增强解释”选择，记住用户选择；初次可默认基础档，此默认属于设计建议。
- 测试：展示场景、输入、输出、断言和实际覆盖，不用一个绿色勾概括未覆盖部分。
- 开发：展示候选变化、差异、原生保存重载结果和相关验证。
- 共享能力：点击图元或解释步骤时关联准确对象与 C/C++ 来源。

早期仍可用任务包与外置 Harness 交换结果，不要求先增加在线模型 API。请求模式与执行进度分开：选择增强档后，页面可以显示等待、运行中、部分验证或测试阻塞。

## Trace Viewer 的位置
浏览器侧操作记录优先复用 Playwright。原生 Java 编辑、图元模型变化、运行值需由相应入口记录并关联同一个任务/步骤。人查看时间线与画面，AI消费结构化事件、状态差异及错误。
本模块不声称记录功能已实现。Trace 回看是诊断证据；业务正确性来自测试断言与需求依据。Canvas/原生场景的内部对象状态需额外结构数据，不能仅凭网页截图认定连接正确。
