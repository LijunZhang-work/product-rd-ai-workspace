# 新旧版本与整理说明

日期：2026-09-18。范围：当前统一工作区、其中两个整包、两个探查任务包，以及 Git 包内保存的资料和工具附件。未修改旧来源工作区、公司代码仓或远程仓库。

## 1. 整理前的问题

第一层只有 Windows与WSL开发环境、产品与EMAP事实探查两个目录，另有两个整包 ZIP 和一份旧说明。先前统一的 9 个模块实际封存在 Git bundle 内；后加内容保存在外层目录。名为“完整文件夹”的旧 ZIP 又嵌套 Git 包，未包含 WSL 目录，增强探查仍为 v1.0。

本次从 Git 包恢复出 131 个文件，核对其提交为 `43e2554a24794181fc56981d15d3e010556d5008`。逐项对比外层现行文件与旧总包，发现增强探查 00～07 共 8 份文档已经变化，08 是后来新增。普通版 5 份文档与原专项包一致。

日期、文件名中的“最新”和 ZIP 修改时间都不单独决定优先级。本轮“现行”限定为已核对的这些输入；没有宣称它们自动等于外部其他工作区或远程仓库的最新状态。

## 3. 展开与保留的边界

正式文档、增强探查执行材料和 HPT 工具源码都直接可读。HPT 项目目录保持自己的 README、依赖清单、示例和测试的相对结构；外层文档用于工作区导航，项目内文档用于这一工具版本的复现。

历史交付包与原始实测证据保留原格式。Trace 和 evidence ZIP 是供工具读取的证据产物，不因整理目录而改写其内部记录。历史方案文档包作为来源备份，不混入当前执行顺序。

原 Git 历史完整保留在旧 Git 包中；当前展开版无需 Git 即可阅读和运行资料检查。旧说明中的“当时未连接 GitHub”保留为历史观察，本轮不据此判断现在的远程连接状态。

### 3 个空日志的保存例外

单独保存下面 3 个原本为 0 字节的历史日志时，保存服务返回 `INVALID_ARGUMENT / LibraryDependencyError`；没有给出更具体的原因。因此未将它们冒充保存成功，也没有给原日志添加内容来改变其字节。

路径均相对于 `产品与EMAP事实探查/成熟工具增强事实探查/`：

- `validation/direct-capture/stdout.txt`
- `validation/selftest/stdout.txt`
- `validation/v1.1/unittest-stdout.txt`

其原始文件完整保存在展开整理版 ZIP 和增强 v1.1 专项包中。直接浏览的工作区已展开其余全部文件；下载完整展开包后，这 3 个空文件也会按原路径还原。工作区文件清单和本轮机械核验针对完整展开目录，包含这 3 个空文件。只下载逐项可见的文件时，会缺这 3 项，应使用完整展开包补齐后再运行校验。
