# 大项目性能、稳定性与安全测试

## 1. 原则

第一优先级是准确性，但系统不能在几十 MB XML 和大型 C/C++ 仓库下卡死。性能设计必须可测、可取消、可降级。

## 2. 关键性能场景

### Workspace打开

只读取入口元数据和POU列表，不立即渲染所有POU。

### Scene

按需生成当前Canvas，缓存结果。

### Code Index

后台增量运行，显示进度。

### Selection

使用空间索引或Web Worker，避免主线程长阻塞。

### Task

任务包只包含选择上下文和引用，不复制整个代码仓。

## 3. 性能基线

建立至少：

```text
Small
Medium
Large
Stress
```

记录：

- XML大小；
-POU数量；
-单POU对象数；
-SVG大小；
-代码文件数；
-compile commands数；
-索引时间；
-峰值内存；
-页面首屏；
-圈选延迟；
-任务导出；
-取消响应。

## 4. 卡死防护

-所有长任务有Job ID；
-进度；
-取消；
-超时；
-内存上限；
-错误恢复；
-部分结果隔离；
-Worker崩溃不拖垮Web。

## 5. 缓存测试

-命中；
-JAR Hash变化失效；
-XML变化失效；
-Exporter版本变化失效；
-损坏重建；
-并发避免重复计算。

## 6. Web压力

-超大SVG加载；
-面板折叠；
-连续缩放；
-100次圈选；
-高频高亮；
-多个Result切换；
-浏览器内存泄漏。

## 7. Code Intelligence压力

-大编译数据库；
-多Profile；
-索引取消/恢复；
-部分文件失败；
-符号查询P95；
-数据流深度限制；
-结果大小限制。

## 8. 安全测试

### 路径

- `..`；
-symlink越界；
-工作区外文件；
-UNC/网络路径策略；
-路径注入。

### XML

- XXE；
-外部实体；
-实体膨胀；
-超深嵌套；
-恶意SVG；
-外部资源加载；
-script标签。

### Task/Result

- Schema欺骗；
-超大字段；
-路径伪造；
-Result引用不存在对象；
-HTML/Markdown注入。

### Code Patch

-越出repo；
-修改禁止文件；
-二进制；
-基线Hash不一致；
-命令注入。

## 9. 降级策略

明确显示：

```text
场景加载失败
代码索引降级
部分POU不可用
分析证据不足
```

不得悄悄丢对象或降低准确性。

## 10. 通过标准

每个阶段设机器可测预算。任何超过预算但不可取消的任务视为P1缺陷。
