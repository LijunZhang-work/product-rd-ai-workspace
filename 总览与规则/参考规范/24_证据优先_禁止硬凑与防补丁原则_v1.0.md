# 证据优先、禁止硬凑与防补丁原则

## 1. 性质

这是所有开发者和模型必须遵守的红线。

## 2. 用户观察的正确用途

用户说：

```text
原生BEH中这里仅有一根线。
```

它是：

```text
Failing Case / Test Oracle
```

不是：

```text
代码规则：始终保留一根。
```

必须追踪多出来的Edge来源和一般性根因。

## 3. 禁止静默去重

若两个Candidate看起来都是A→B：

禁止直接集合去重或保留第一条。

必须区分：

-同一origin重复解析；
-不同relation；
-不同Port；
-不同Scope；
-隐式/可见；
-解析错误。

无法解释时标：

```text
DUPLICATE_AMBIGUOUS
```

## 4. 禁止偷偷删线

错误流程：

```text
用户说多了一根
→ 删除第二根
```

正确流程：

```text
保留Raw Candidate
→ 查origin
→ 查scope/port/family
→ 证明为何Reject
```

## 5. 禁止确认偏差

不得先相信用户或模型结论，再从XML/代码中挑选支持证据。必须同时找：

-正证据；
-反证据；
-相似反例。

## 6. Raw不可覆盖

```text
Raw
Normalized
Reviewed
Rendered
```

必须保留。Review不能改写Raw历史。

## 7. Renderer无语义权

Renderer不得：

-补线；
-删线；
-去重；
-翻方向；
-按坐标连线；
-隐藏正式Edge。

## 8. UNKNOWN合法

UNKNOWN比假确定更好。任何不确定字段不允许用默认值伪装。

## 9. Relation身份不可忽略

A→B拓扑对，但origin relation错，仍然是错误。

## 10. 修复提交要求

必须写：

```text
Root Cause
Evidence
General Rule
Changed Code Path
Positive Test
Negative Test
Regression Test
Remaining Unknown
```

## 11. 规则不得使用具体工程ID

允许：

```text
Relation Family结构规则
```

禁止：

```text
if relation_id == "relation_10"
```

除非这是测试Fixture中的断言，而非产品逻辑。

## 12. 测试真值保护

测试失败不得修改Expected来通过，除非有独立证据证明Expected错误，并保留审计记录。

## 13. 原生证据优先

原始JAR/Headless结果和原生BEH可重复行为高于AI解释。
