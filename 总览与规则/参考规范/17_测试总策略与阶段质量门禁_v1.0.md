# 测试总策略与阶段质量门禁

## 1. 核心原则

本项目面对：

- 私有 BEH 运行时；
- 大型 XML；
- 原生 SVG/Scene；
- Web复杂交互；
- C/C++代码索引；
- 外置模型Skill；
-后期原生写入。

因此不能依靠单一单元测试。采用分层测试金字塔：

```text
Unit
Contract
Golden
Integration
Playwright E2E
Performance
Security
Round-trip
```

## 2. 完成声明规则

任何阶段不得仅凭：

- 编译通过；
-类型检查通过；
-测试文件存在；
-模型声称完成；
-截图看起来正常；

宣称完成。

必须提供阶段验收表。

## 3. 测试层

### Unit

纯函数和算法：

- Hash；
-路径校验；
-Selection geometry；
-Relation相交；
-Schema validation；
-结果联动映射；
-状态机。

### Contract

跨服务JSON：

- NativeScene；
-Selection；
-Task；
-Result；
-Proposal。

### Golden

对已知小POU和代码仓，结果固定：

- Native IDs；
-Relation；
-Arrow；
-选择命中；
-分析步骤；
-绑定Evidence。

### Integration

- Java Scene Service + Gateway；
-Gateway + Web；
-Code Intelligence + Skill tools；
-File Adapter；
-Harness Adapter；
-原生Apply + Reload。

### Playwright

真实浏览器运行态和用户流程。

### Performance

大场景、大代码仓、并行任务、缓存与取消。

### Security

路径、XML、SVG、任务包、代码Patch和日志。

### Round-trip

AI开发能力的最终门禁。

## 4. 阶段门禁

### 阶段0

- Headless重复输出确定；
- scene/svg/json/hitmap一致；
- Golden场景通过；
-无JCanvas依赖；
-大POU内存受控。

### 阶段1

- Playwright核心流程全部PASS；
-页面无框架错误Overlay；
-Console无阻塞错误；
-面板折叠正常；
-选择准确；
-任务包Schema通过。

### 阶段2

- 10个分析Golden；
-每个步骤有focus/evidence；
-专业/小白事实一致；
-无Evidence高置信断言为0；
-结果导入联动通过Playwright。

### 阶段3

-代码绑定Precision/Recall有基线；
-降级模式正确；
-同名符号和宏测试；
-代码跳转准确；
-大仓索引性能达标。

### 阶段4

- Proposal不越权；
- Schema通过；
-影响报告完整；
-代码补丁在临时worktree验证；
-正式工程无修改。

### 阶段5

-事务回滚；
-Round-trip语义等价；
-构建/测试；
-失败不提交。

### 阶段6

- FileAdapter/HarnessAdapter契约一致；
-断线、取消、幂等；
-Harness升级回归。

## 5. 缺陷严重度

### P0

- 原生场景身份错误；
-数据丢失；
-正式工程被意外修改；
-越权访问；
-静默删线/去重；
-错误结果标为PASS。

### P1

-核心流程不可用；
-选择错误；
-分析步骤定位错对象；
-代码补丁基线错误；
-大项目卡死无取消。

### P2

-非核心UI问题；
-性能退化；
-个别非关键显示问题。

## 6. 测试数据隔离

- 公开/合成样本用于CI；
-公司真实数据只在公司环境；
-脱敏Golden可输出结构Hash；
-真实XML不得写入模型日志；
-测试结果必须记录JAR/XML/代码commit Hash。

## 7. 回归要求

每个修复都必须增加：

```text
正例
反例
相邻场景
历史Golden
```

禁止只验证当前一个失败样本。
