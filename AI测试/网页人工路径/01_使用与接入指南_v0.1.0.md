# 使用与接入指南 · v0.1.0

## 1. 交付目标与读者分工

用户只需要说明“从哪里开始、依次怎么操作、应该看到什么”。实施助手负责建立路线和模型连接，固定执行器负责执行与判定。用户审查报告中的业务步骤与页面截图，无须逐行检查 Python。

本版交付的是本地命令行 MVP，包含真实浏览器演示、完整源码、测试、依赖锁、模型配置模板和安装 wheel。未交付托管服务或已连接的生产系统。先按 README 安装并运行 `python -m hpt demo --functional-only`，确认安装有效，再接真实页面。

## 2. 推荐工作顺序

| 阶段 | 输入 | 输出 | 放行条件 |
|---|---|---|---|
| 描述业务 | 人的操作与独立预期 | intent.md、参数、环境 | 入口、角色、数据范围明确 |
| 多模态探路 | 本次图片、语义控件、意图 | candidate.json 与探索证据 | 每个动作绑定最近观察；done 只结束探索 |
| 整理用例 | 候选、独立 outcomes.json | 四个正式用例文件 | 预期没有覆盖探索动作目标 |
| 固定程序重放 | 用例、具体输入 | 截图、断言、Trace、结果 | 新上下文、完整入口到终点、证据齐全 |
| 视觉验收 | 本次关键截图 | 模型检查或独立评估 | 每个要求明确 pass/fail/uncertain |
| 版本复用 | 精确匹配的通过证据 | 不可覆盖版本 | 变更后重放旧输入；新输入先 adapt |

多模态模型只在探路与视觉判断时参与，稳定执行无需再次让模型猜操作。文字模型的维护入口已经实现；没有模型也能直接重复执行通过验证的路线。

## 3. 从示例建立自己的用例

解压源码包，按 README 安装。命令均在项目根目录、已激活虚拟环境中运行。

```bash
python -m hpt init-demo my-case
python -m hpt validate my-case
```

`validate` 只验证规格，不能代替浏览器。`my-case` 的示例控件与本地夹具对应，不能直接用于你的产品。真实接入由助手重新探路，用户提供以下内容即可：

- 测试环境 URL、应用版本、测试角色。
- 人如何登录、完成该任务；哪些步骤属于本次覆盖。
- 输入例子、正确结果、容易出错的情形。
- 测试数据如何隔离、清理；是否允许提交新增或删除。

当前不注入 Cookie 或 Storage 登录状态。若登录属于测试路径，必须通过实际 UI 纳入路线。系统验证码、单点登录弹窗和多页面流程未实现通用适配，不能偷偷绕过。

环境文件可参考 `examples/explored/environment.json`。`entry_url` 是允许的起点；`allowed_origins` 是来源检查列表；`app_build` 和 `role` 是运行声明；视口、语言与时区要与测试要求一致。来源列表不是网络防火墙。

## 4. 模型配置

复制 `examples/vision-model.example.json` 为私有 `vision-model.json`，填写自己的兼容服务 endpoint 和 model。文字模型参考 `examples/text-model.example.json`。示例地址 `.invalid` 刻意不可访问，不能直接运行。

密钥放到配置的 `api_key_env` 环境变量，默认 `HPT_MODEL_API_KEY`。不要把密钥写进路线、参数、模型 JSON 或交付证据。图像服务必须声明 `supports_images=true`；`token_limit_field` 可按服务要求选择 `max_tokens` 或 `max_completion_tokens`。HTTP 仅允许本地回环测试，远程使用 HTTPS。

```bash
python -m hpt doctor --model vision-model.json
```

doctor 检查浏览器可启动、配置可读、凭据是否存在，**不做真实模型调用验证**。外部服务对协议、限额和视觉输入的支持仍要通过一次实际探路确认。已实现的是 Chat Completions 兼容协议，不保证任何供应商配置都可直接使用。

## 5. 真正的图像先行探路

准备 `intent.md`、`parameters.json`、`inputs.json`、`environment.json`。本次实际探索的可参考样例在 `examples/explored/`。

```bash
python -m hpt explore --intent intent.md --environment environment.json --parameters parameters.json --inputs inputs.json --model vision-model.json --output explorations
```

若使用现有能看图的助手，将 `--model vision-model.json` 换成 `--stdio`。这不是让使用者手写 JSON：宿主助手读取每次输出的 request 文件与截图，真正查看图片，再将 `{image_sha256, model_id, decision}` 提交给运行进程。截图摘要必须匹配，动作必须使用最新 observation_id。不能从旧截图猜下一页。

该入口不是通用桌面插件自动发现机制；当前宿主需要有读图片和进程标准输入能力。本次交付已按这个通道完成真实看图探索。

每一步只有受限数据动作，没有业务 API、任意 JavaScript 或 shell 字段。超预算、非法输出或观察过期均停止，不能修改规则来凑成功。结束时得到候选路线，仍需独立预期与重放。

## 6. 独立预期与编译

由助手根据用户描述另建 `outcomes.json`，包含需要检查的控件、断言与关键截图要求。不能把页面当前错误值抄成正确预期。本项目实例检查保存提示、对话框关闭、刷新后的唯一设备行与设备类型。

```bash
python -m hpt prepare-case explorations/<run_id> --outcomes outcomes.json --destination candidate-case
python -m hpt validate candidate-case
python -m hpt run candidate-case --vision-model vision-model.json --output artifacts
```

目录占位符替换为命令打印的真实路径。candidate-case 必须是新目录。新的输入写入 `inputs.json`，由严格参数检查验证；动作和预期变化则需要新的业务契约。

可选文字维护：

```bash
python -m hpt compile candidate-case --model text-model.json --destination route-v2.json
```

产物是新候选 route 文件，不自动发布、不替换旧用例。复制完整用例为新目录后采用新 route，再 validate 和完整重放。编译器拒绝改变冻结动作、目标与检查点；它当前不承担任意新流程自动迁移。

## 7. 怎样读结论

| 结果 | 应当如何处理 |
|---|---|
| PASS | 声明范围内的固定 Runner UI 检查通过；仍需看 certification 范围 |
| FAIL | 保留第一失败及证据；区分产品、路线、数据、环境原因，不自动绕路 |
| INCOMPLETE | 缺视觉检查、预期待确认等；不能当作成功 |
| BLOCKED | 环境或运行前置受阻；先解决前置 |
| UNSUPPORTED | 当前受限动作无法覆盖该能力；需要独立适配 |

`failure_category=UI_OR_ROUTE` 不等于已经证明产品 Bug；需要结合截图和只读诊断判断。功能与视觉分别报告，`--functional-only` 只能用于显式缩小范围的专项。

命令返回码：PASS=0、FAIL=1、无效规格=2、INCOMPLETE=3、BLOCKED=4、UNSUPPORTED=5。CI 应保存非零退出运行的证据，不要只上传成功文件。

```bash
python -m hpt report artifacts/<run_id>
python -m hpt integrity artifacts/<run_id>
python -m playwright show-trace artifacts/<run_id>/trace.zip
```

`report.md` 可直接打开看动作与截图，CLI report 输出结果和完整性状态。Trace 可能包含页面信息，应按测试资料的权限管理。网络诊断是页面自身请求的只读记录，不会主动调业务 API 完成步骤。

## 8. 视觉复核与证据更新

没有视觉服务时，程序不会自行把 screenshot 的存在判为视觉通过。可由实际看过图片的人或多模态助手提供外部 review，结构参考证据包中的 `visual-assessment/*/review.json`。

```bash
python -m hpt review artifacts/<run_id> review.json --output assessments
```

它先检查原始完整性，再核对每张图的 SHA256 和所有检查项。新 assessment 保留原结果，仅添加新的视觉判断；不会把旧 INCOMPLETE 文件改成 PASS。外部评审身份属于声明，不是经过签名认证的证明。

若完整性失败，停止引用该运行作通过依据。保留损坏原件，重新运行；不得更新摘要来掩盖变化。

## 9. 回归与版本库

`suite.json` 内容例子：`["cases/create", "cases/search"]`，目录相对 suite 文件。

```bash
python -m hpt regression suite.json --vision-model vision-model.json --output artifacts
python -m hpt publish candidate-case --registry registry --runs artifacts/<passed_run_id>
python -m hpt recommend device.create --registry registry --inputs candidate-case/inputs.json
```

case_id 以实际 route 为准。发布入口需要原始运行的匹配 PASS，不把独立外部 assessment 自动冒充原运行。新增版本不可覆盖旧版本，必须提供旧输入在新版本上的重放证据。当前 exact 输入给 run，新输入给 adapt，不能把一次成功推广到全部组合。

## 10. 数据、安装包与维护

demo 自动创建独立内存 SQLite 环境并在结束后销毁；这是夹具生命周期，不是通用真实系统数据清理。普通 run 的 cleanup 为 not_run；真实系统需要明确的 UI 删除用例，清理失败单独记录。不能为获得 clean rerun 直接删真实数据库。

源码包 `dist/` 包含 wheel，可在完成锁定依赖安装后执行 `python -m pip install --no-deps dist/human_path_testing-0.1.0-py3-none-any.whl`。不要同时混用编辑安装与 wheel 来做独立安装验收。

升级流程：保存旧版本→修改→运行测试→独立上下文重放→另进程复核证据→新版本收录。依赖锁不包含操作系统或浏览器；目标机器必须另外验收。项目没有自动更新生产系统的行为。
