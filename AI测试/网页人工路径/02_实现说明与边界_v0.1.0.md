# 实现说明与边界 · v0.1.0

日期：2026-09-13。此文描述交付代码的实际行为；原设计文档保留为架构依据，不把规划中的功能算成已完成。

## 1. 已实现模块

| 模块 | 实际实现 |
|---|---|
| `contracts.py` | 严格 Pydantic 模型、动作枚举、字段形状、参数、引用、作用域循环检查、独立业务契约比对 |
| `runner.py` | 固定 Playwright 映射、正常点击、聚焦后输入、选择、按键、滚动、刷新、前进历史的返回、断言、独立上下文 |
| `evidence.py` | 唯一运行目录、实时事件、同步写入、结束时原子快照、校验清单、后续完整性复核 |
| `models.py` | Chat Completions 兼容传输，图像字节与摘要记录；现有助手的 stdio 入口 |
| `explorer.py` | 图像先行探索、观察编号约束、有限动作预算、候选路线、独立预期装配、文字模型维护 |
| `vision.py` | 本次截图逐项视觉判定；缺项/模型异常不能通过；外部视觉复核形成新评估，不覆盖旧结果 |
| `registry.py` | 不可覆盖的版本目录、匹配回放证据、保留旧输入覆盖、保守推荐 |
| `fixture.py/html` | 本地设备管理应用、SQLite 保存、可重复故障配置；测试数据与真实服务隔离 |
| `cli.py/reporting.py` | 安装检查、运行入口、报告、完整性检查、对比、回归、示例与 Schema 导出 |

没有另造浏览器引擎、通用 Agent 编排器或新重型管理界面。

## 2. 实际路线格式为 1.1

可运行格式是 `schema_version=1.1`，不同于两份早期设计中的 YAML 或 JSON 示意。以 `hpt schema` 的导出和 `hpt validate` 的语义规则为准。

每一步绑定 `business_id`，独立 `behavior.json` 冻结动作顺序、目标语义和检查点。当前采取保守的精确一致检查：正常改参数不用改动作；改定位语义或预期必须形成新契约与重放。没有隐藏的任意代码逃生口。

`prepare-case` 把真实探索路线与另行提供的预期拼成用例；预期不能覆盖探索中的操作目标。它不会把当前页面反向当成正确答案，也不会因为模型发出 done 就发布通过结果。

## 3. 通过结论有两个范围

| 字段 | 定义 |
|---|---|
| `overall` | 本次固定 Runner 通道内、声明范围内的 UI 测试结果 |
| `certification` | 对整个执行环境隔离和完整人工等价的认证；当前不提供，正常运行也为 INCOMPLETE |
| `functional` | 程序断言是否通过 |
| `path` | 当前 Runner 是否按冻结数据执行、有没有触发已实现策略 |
| `visual` | 本次视觉要求通过/失败/不确定/未检查，或用例显式不要求 |
| `evidence` | 结论必需文件与记录是否齐全 |

这是对早期“Human-path Verified”口径的收紧。用户不需要读代码，但报告也不能制造超过证据范围的保证。

## 4. 可以阻止与尚不能保证的事

可以在路线通道中拒绝：业务 HTTP 动作、任意 JS、Storage 写入、Mock 成功、强制点击、动态方法、未知字段、中途再次直达入口、缺失检查点、删除步骤、替换预期、错误参数类型。按钮被挡住时不会删除遮罩或改用接口。

固定执行器会做少量只读浏览器检查，例如读取计算样式判断透明元素；这些是已写在程序中的固定代码，不接受模型传入表达式。普通应用自己的 API、存储和 JS 必须正常工作。

尚不保证：其他主机进程不能操作同一产品、外部浏览器控制完全被隔离、网络请求来源具有完整因果证明、视觉模型永远判断正确。URL 源检查包含点击前普通链接检查和导航后检查，**不是网络防火墙**，不能保证所有跨域副作用在发生前都拦住。

因此此版本适合作为可审计本地 MVP；不能单凭它宣布“恶意任意代码不可能绕过”或“所有人工测试已被替代”。

## 5. 输入与特殊控件

普通文本可在声明点击/聚焦后 fill；逐键专项用 type_text；按键仅接受有限枚举。自定义下拉通过打开、点击选项执行，原生 select 有独立动作。

本版未实现：真实中文输入法、系统文件窗口、Canvas/BEH 图元适配、原生 Java 窗口、多窗口与弹出窗口工作流、通用上传下载适配。遇到这些范围要停止或明确不支持，不能调应用内部函数冒充人工路径。

## 6. 留档问题与修复

初版在运行内部验证通过后，跨工具读取部分 JSONL 事件文件发现其内容与冻结摘要不一致；复核和发布入口拒绝了这些证据。旧运行没有被重新封口或覆盖为成功。

修复方式：事件每次都用完整顺序记录发布原子快照，避免延迟追加写回覆盖快照；关闭浏览器并结束观察后再发布最终快照，再计算摘要；结论生成前检查截图引用、断言覆盖与动作序列。最终测试后另起读取过程复核证据。此修复针对观察到的留档问题，不把摘要称为能对抗同权限篡改的加密审计。

## 7. 模型接入的验证状态

- 已用当前能看图的助手，通过 stdio 对实际截图逐步探路，形成候选路线，并换参数完成程序重放。
- 已用本地协议服务验证图像字节发送、非视觉模型拒绝图像、文字编译器保持业务契约、错误输出被拒绝。这些是协议测试，不是对真实模型智力的验证。
- 外部视觉服务和独立非视觉模型供应商尚未在线验证：当前没有目标供应商配置与 API 密钥。相关接口和错误路径已实现，不能把本地协议服务称作真实大模型。
- 关键重放截图由当前助手实际看图复核，结果作为独立外部评估保存；身份属于声明，未做密码学认证。

## 8. 后续真实接入所需信息

首个测试系统地址、允许的测试账号/角色、应用版本、用户操作与预期、数据准备与清理方式，以及需要的模型连接配置。仅收集这些实际接入信息即可，不需要使用者审查 Python。

当前已有包、示例与说明可以在没有生产账号的情况下运行本地演示；真实产品接入与跨平台实机验证必须在对应环境完成，不能用夹具通过替代。

交付补充：部分托管目录在后续同步后仍出现文本记录变化。因此每次 seal 同时保存不可覆盖的 `<run_id>.evidence.zip` 二进制快照，位于运行目录旁；交付以另进程逐个验证过摘要的完整压缩快照为准。原始目录若完整性失败仍拒绝使用。可解压快照到新目录后运行 integrity；这恢复的是原始已封存字节，不重新生成摘要或更改结果。
