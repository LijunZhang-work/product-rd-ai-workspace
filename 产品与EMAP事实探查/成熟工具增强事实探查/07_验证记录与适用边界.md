## 3. 当前尚未验证的部分

没有实际产品仓、EMAP 仓、SDK、板端编译目标或真实固件输入；没有分析出产品核数、后端、消息机制或根因。主机样例不证明 RTOS、异构核、缓存一致性、实时性或 BEH 图元行为。

v1.0 的环境记录显示可用 Python、GCC/G++、GNU readelf/nm/objdump，未使用真实 Clang、CodeQL 或 Bear 引擎。v1.1 的 44 项自测也未执行这些分析引擎，更未验证用户的 WSL 或产品容器。工具执行手册与查询依照已核对官方资料编写，具体版本兼容性必须在实际执行机确认。

CodeQL 初始查询须先解析本地依赖并保存锁文件、填写真实 Scope，再实际运行；如果 API 版本不兼容或查询有误，由本地 AI 修正、保存差异并重跑。CodeQL 适配器测试中的假 CLI 只检查错误传递与结果处理，它没有验证任何 QL 语义。

## 4. 辅助脚本具体限制

- compdb 检查是命令清单和文件级检查，不解释所有编译选项、不验证目标 ABI、不证明实际链接；响应文件只记录存在与摘要。
- compare-definitions 比较函数定义出现的文件集合；不代表全部翻译单元、宏配置、模板或控制流覆盖。
- baseline 保存 Git 身份/差异摘要，不是完整源码快照，也不完整保存未跟踪文件和子仓脏内容；关键输入另行归档。
- record 保存执行与声明输入摘要，不自动捕获完整环境、所有被读取头文件或后台子进程的最终结果；必须核对工具所需输出和完成状态。它不是沙箱。
- validate-ledger 只检查引用、摘要、标签和最低证据种类，不判断原证据真实或 AI 推理正确，也不把仍有未知的账本判作整个项目完成。
- check_workflow 只检查声明状态、引用文件和入口导航；同一个无效说明文件也可能通过文件存在检查，必须按 03 复核内容，不能把通过状态当真实工具运行证据。
- run_codeql 执行提供的初始盘点查询；不会自动完成别名分析、闭源建模、跨语言/跨核关联、图元绑定或故障因果证明。

## 5. 本地执行前后的必需验证

首先在真实目标上核对编译参数与关键后端，再实际执行 Clang/CodeQL 并确认覆盖与错误。按 03 的代表性准确性检查核验同名实现、目标宏差异、预编译 EMAP、注册关系和漏采处理。最后把真实工具结果、产物身份和内容复核写入 G0～G7，才形成受范围约束的事实报告。

本包的辅助测试可在本地再次运行用于检查移植；真实项目结论仍必须来自真实双仓和对应产物。
