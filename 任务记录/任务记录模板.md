# 任务记录模板

这是后续任务的记录模板，不是已执行任务，也不是要求所有工具采用统一 Schema。

| 项目 | 填写内容 |
| --- | --- |
| 任务 | 标识、业务问题、范围、状态 |
| 输入与基线 | 需求、源码/图元/工具/配置版本和对应关系 |
| 场景与预期 | 触发入口、步骤、独立预期及依据 |
| 运行列表 | 每次运行的编号、环境、时间、执行结果及异常 |
| 工具角色 | 网页、北向、南向 Python、专用 RS-485、BEH、日志/报文分别记录 |
| 证据位置 | 原始包、Trace、截图、值记录、解析结果及实际取得的校验值 |
| AI解释 | 结论、来源、适用条件、推断和未覆盖范围 |
| 定位与开发 | 定位材料、候选修改、提交与回归记录 |

同一任务可以有多次运行。组件自身的发行验证仍归该组件；针对产品的运行在这里建立索引。一个 run_id 只能帮助关联，不直接证明事件因果。

## 真实场景、采集与回放补充

按[真实场景入口](../真实场景集成验证/00_总入口与执行约定.md)记录适用步骤及状态，细项使用[用例与映射模板](../真实场景集成验证/端到端用例与POU验证/02_用例映射与执行记录模板.md)。本任务引用一份版本明确的双仓事实、XML/绑定和工具报告，不重复维护。

| 项目 | 追加内容 |
| --- | --- |
| POU 执行条件 | 参数、状态/预热、输入/事件序列、时间推进、模式/质量/使能及外部依赖 |
| 采集身份 | capture_id、各域 build/boot_id、模型/实例、点位、消息/数据版本、调用/周期/阶段 |
| 观测资格 | 值的来源与复制时机、GUI/Debug 状态、丢失/覆盖/未导出、时间校准、采集扰动 |
| 三方对照 | 板端实际、离线实际、独立预期及其依据分列；不复制 actual 生成 expected |
| Review 与复跑 | 发现、影响、修正、受影响检查结果、未解决缺口及续接点 |

无板端数据、无独立预期或状态不完整时明确标出，对应结论保留边界。文档更新任务不填成产品运行记录。
